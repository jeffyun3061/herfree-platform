# 사이트 운영자·개발자 사용 및 개선 기준

2026-10-11 코드 확인 기준. 구현된 화면과 추가 계획을 구분한다. AWS 실제 접근 권한과
새 MFA의 운영 적용 완료는 로그인 갱신·staging/production 검증 기록으로 확인한다.

## 사이트 운영자: 브라우저에서 처리

일반 계정으로 로그인한 뒤 운영 권한을 가진 계정은 `https://www.herpfree.co.kr/admin`을
사용한다. 추가 운영자는 기존 최고 관리자가 회원 탭에서 권한을 부여한다. 코드·DB·AWS
콘솔을 일상 업무에 사용할 필요는 없다. 신규 MFA 배포 후에는 본인 확인 및 인증앱 등록을
거쳐 15분 단위 추가 인증으로 관리 기능을 사용한다.

| 업무 | 현재 코드의 화면과 기능 |
|---|---|
| 현황 | `/admin?tab=dashboard`: 회원/신규 회원, 글·댓글, 대기 신고, 콘텐츠 수 및 7일 사용 집계 |
| 회원 | `/admin?tab=users`: 이메일·닉네임·내부 ID 검색, 정지/해제, 제재 사유·기간·운영 메모, 닉네임 초기화 |
| 권한 | 최고 관리자만 회원 역할 변경; 일반 ADMIN은 회원 상태 관리 |
| 신고 | `/admin?tab=reports`: 대기/승인/반려, 누적 신고 검토, 대상 숨김·삭제 및 제재 검토 연결 |
| 게시물 | `/admin?tab=moderation`: 글·댓글 검색, 숨김/복구; 필요 시 개별 글 수정·삭제 |
| 발행 | `/admin?tab=notices`, `contents`, `videos`: 등록·수정, 노출 및 정렬/고정 설정 |
| 문의 | `/inquiry`, `/consult`의 운영 문의 목록/개별 글에서 운영자 답변; 의료 진단·처방 기능은 제공하지 않음 |
| 일지 | `/admin?tab=journal`: 집계 지표. 개인 메모 원문 열람 기능은 제공하지 않음 |

담당자는 매일 대기 신고·미답변 문의를 확인하고 조치 사유를 남긴다. 회원 문의로 장애가
의심되면 발생 시각, 화면/기능, 내부 회원 ID, 오류의 request ID를 개발자에게 전달한다.
비밀번호, MFA 코드, 개인일지 본문을 장애 보고에 복사하지 않는다.

## 개발자: 로그·인프라·배포 관리

개발자의 AWS/GitHub 권한과 사이트 회원 권한은 별개다. 개발자가 된다는 이유로 사이트
SUPER_ADMIN을 부여하지 않는다. 사이트 회원 조치는 사이트 운영자가 처리하며, 개발자는
기술 조사에 필요한 범위만 접근한다. 같은 사람이 두 업무를 담당할 때도 각각 기록한다.

| 업무 | 현재 도구/확인 위치 |
|---|---|
| 장애 로그 | AWS CloudWatch → Log Management → `/herfree/production/api` → 발생 시각/request ID로 검색 |
| 서버 상태 | CloudWatch EC2/`Herfree/Operations` 지표·알람; 서버 메모리/디스크 추가 지표는 AWS 적용 전 |
| 서버 관리 | 기존 SSM 연결 성공 확인 후 제한된 IAM으로 대상 EC2에 접속; 외부 DB 포트를 열지 않음 |
| 배포 | GitHub Actions CI/CodeQL → staging 검증 → 배포 전 백업 → production release → smoke/필요 시 rollback |
| 백업 | 6시간 백업 완료 파일·체크섬, 일일 백업, EBS 스냅샷, 월간 격리 복원 및 정리 결과 |
| 비용 | Cost Explorer 서비스별 최근 비용·사용량, Budgets 알림, ECR 보호 이미지와 정리 dry run |
| 보안 | 취약점 검사, 최소 IAM, MFA, 키 복구 가능 여부, 민감정보 로그 노출 점검 |

CloudWatch의 로그 열람은 해당 로그 그룹에 제한된 읽기 권한을 기본으로 한다. 배포·SSM·
복구 키 접근은 업무에 필요한 역할에만 부여한다. SSM 서버 shell 권한은 DB/키 접근까지
이어질 수 있으므로 단순 로그 조회 개발자에게 기본 부여하지 않는다.
[AWS 로그 조회](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/Working-with-log-groups-and-streams.html),
[AWS SSM 접근](https://docs.aws.amazon.com/systems-manager/latest/userguide/session-manager.html).

로그에는 요청/응답 본문·토큰·비밀번호·일지 메모를 저장하지 않는다. 현재 관리자 요청은
`admin_audit_logs`에 수행자·시각·경로·HTTP 상태·request ID를 남기고, 회원 권한/제재는
`role_audit_logs`에 기록한다. 이 두 이력을 조회하는 관리자 API/화면은 아직 없다.

## 추가 대시보드 기능 계획

| 사이트 운영자 | 개발자 |
|---|---|
| 오늘 처리할 신고·미답변 문의 및 경과 시간 | 서비스 상태·5xx 비율·응답 지연 및 마지막 수집 시각 |
| 신규 회원·활성 이용·새 글과 추이 | CPU·메모리·루트/DB 디스크·DB 상태 |
| 회원 검색·조치 바로가기 및 사유 입력 | 현재 배포 SHA/digest·CI·staging 결과·rollback 버전 |
| 공지·칼럼·영상 발행 바로가기 | 최근 성공 백업·지연·복구훈련/RPO/RTO 결과 |
| 누가 언제 무엇을 조치했는지 조회 | 서비스별 월 비용/예상 비용·예산 도달 상태 |
| 정상/점검 필요/개발자 확인 중으로 표시하는 서비스 안내 | request ID 기반 로그 검색 연결 및 장애 대응 기록 |

운영자 화면은 비기술 용어와 조치 버튼을 사용하고 장애 상세는 개발자 도구로 연결한다.
개발자 전용 웹 대시보드, 운영자 문의 대기 카드, 감사 이력 조회는 **추가 계획이며 이
변경으로 구현·운영 배포된 기능으로 표시하지 않는다**. 이후 구현 시 사이트 역할과
기술 운영 권한을 서버에서 분리하고, 통계/상태에 회원 이메일·건강정보 원문·비밀 값을
포함하지 않는다. AWS 값 조회 실패/수집 중단은 정상으로 표시하지 않는다.
