# 사이트 운영자·개발자 사용 안내

2026-10-11 후보 코드 기준. 아래 화면은 구현되었으며 운영 적용 여부는
[배포 검증 기록](operations-validation-2026-10-11.md)으로 확인한다.
사이트 역할, AWS 접근 권한, GitHub 배포 권한은 서로 별개다.

## 사이트 운영자

로그인 후 `https://www.herpfree.co.kr/admin`을 사용한다. 코드나 DB 명령을 알 필요가 없다.
최고 관리자가 회원 메뉴에서 ADMIN 권한을 부여한다. 최초 MFA 등록은 운영 책임자의
본인 확인과 일회용 등록 승인을 거친다. 인증앱으로 추가 인증하면 15분 동안 관리 기능을
사용할 수 있다. 등록·복구 절차는 [개선 실행서](operations-improvements.md)를 따른다.

| 메뉴 | 기능 |
|---|---|
| 대시보드 | 회원·신규 회원·게시물·댓글·신고·7일 사용 지표, 미답변 문의/비공개 문의 수와 가장 오래된 5건 |
| 오늘 처리할 일 | 24시간 넘은 신고/문의 표시, 문의 답변·신고 처리·회원 검색·공지 발행 바로가기 |
| 회원 | 이메일·닉네임·내부 ID 검색, 정지/해제, 사유·기간·운영 메모, 닉네임 초기화 |
| 권한 | 최고 관리자만 역할 변경. 일반 ADMIN은 회원 상태 관리 |
| 신고·숨김 관리 | 신고 승인/반려, 대상 숨김·복구 및 제재 검토 연결 |
| 공지·칼럼·영상 | 발행·수정, 노출·정렬/고정 설정 |
| 운영 이력 | 최근 1/7/30일 관리 변경 및 회원 권한/상태 변경. 수행자/대상 ID 검색, 페이지당 20건 |
| 일지 통계 | 집계 지표. 개인 메모 원문은 제공하지 않음 |

미답변 문의는 활성 게시물에 다른 운영 담당자(MODERATOR/ADMIN/SUPER_ADMIN)의 활성 댓글이
없는 경우다. 작성자 자신의 댓글, 숨김 댓글, 개발자 댓글은 운영 답변으로 계산하지 않는다.
대기 카드에는 문의 본문·제목·회원 이메일이 포함되지 않는다. 문의 상세는 기존 권한 검사를
거쳐 열린다. 운영 이력에는 내부 ID, 시간, 조치, 결과만 제공하고 사유·메모 원문은 제외한다.
기존 감사 기록 보관 기간 365일은 유지한다. 화면 검색 기간은 최대 30일이다.

매일 대기 업무를 확인하고 실제 조치 사유를 남긴다. 장애는 발생 시각, 화면/기능,
내부 회원 ID와 오류의 요청 ID를 개발자에게 전달한다. 비밀번호·MFA 코드·일지 본문은
장애 보고에 복사하지 않는다.

## 개발자

최고 관리자가 필요한 계정에 DEVELOPER 역할을 부여하면 로그인/MFA 후
`/admin?tab=developer` 또는 마이페이지의 개발자 진단 링크로 접속한다.
DEVELOPER는 기술 진단만 사용할 수 있다. 회원 정지·권한 변경·콘텐츠 운영·다른 회원의
비공개 상담 열람 권한을 부여하지 않는다. SUPER_ADMIN도 진단 화면을 사용할 수 있다.
일반 ADMIN은 기술 진단 API에 접근할 수 없다. 역할 변경·정지 시 기존 로그인과 MFA
증명이 폐기된다. 모바일에서도 같은 서버 권한 검사를 적용한다.

| 진단 화면 | 확인 내용과 범위 |
|---|---|
| 실행 환경 | 환경, 현재 이미지 SHA/digest, API 가동 시간, JVM 힙 사용량 |
| DB | SELECT 1 연결 상태, MySQL 버전, 마지막 Flyway 버전/결과, 연결 풀 사용·대기 |
| 테이블 용량 | 최대 100개 테이블의 MySQL 추정 행 수, 데이터+인덱스 용량. 데이터 원문/SQL 실행 없음 |
| 서버·백업 | 서버 메모리, 루트/DB 디스크, 공개 HTTPS, DB 상태, 마지막 백업/복구 성공 시각, 최근 복구 시도 |
| 요청 로그 | 현재 API 프로세스 최근 1시간/최대 1,000건 중 최근 50건, 오류 필터, 정확한 요청 ID 검색 |

요청 로그는 시각·요청 ID·메서드·프레임워크 경로 템플릿·HTTP 상태·응답 시간만 저장한다.
본문·검색어·회원 정보·토큰·예외 원문은 수집하지 않는다. 재시작하면 초기화되며 보관 범위의
5xx 건수/최대 응답 시간은 전체 트래픽 통계가 아니다. 5xx 또는 2초 이상 요청의 메타데이터는
기존 서버 로그에도 남는다. 장기 로그는 CloudWatch `/herfree/production/api`에서 조회한다.

API 상태 조회는 15초 동안 재사용된다. 서버 지표는 기존 5분 모니터가 root 소유 JSON을
원자적으로 갱신하고 API 컨테이너는 읽기 전용으로 마운트한다. 수집 중단/10분 초과/잘못된
환경·시각·형식은 정상으로 표시하지 않는다. 배포만으로 CloudWatch 경보나 복구훈련 성공이
생기지는 않는다. 모니터 설치와 실제 알림 도달/복원 검증은 별도로 기록한다.

배포·롤백은 GitHub Actions, 장기 로그·경보는 CloudWatch, 서버 관리는 기존 SSM을 사용한다.
단순 로그 조회 담당자에게 서버 shell·DB·비밀 키 접근을 기본 부여하지 않는다.
AWS 읽기 권한은 대상 로그/지표에 제한하며, 배포·복구 권한은 필요한 담당자에게만 부여한다.

## 후속 측정과 남은 작업

실시간 AWS 비용 카드, CPU 그래프, CI/롤백 조작 버튼은 이번 웹 대시보드에 포함하지 않는다.
기존 Cost Explorer/Budgets/CloudWatch/GitHub를 사용한다. 새 유료 관측 서비스를 추가하지
않으며 30일 메모리·사용량 측정과 실제 모니터링 비용을 함께 비교한다.
운영 담당자 지정, MFA 본인 확인, 실제 AWS 알림 도달·격리 복구 및 배포 후 기능 확인은
코드 검사와 구분한다.
