Herfree 법률 검토 의견서
(체크리스트 작성본)

herpfree.co.kr · 검토 기준일 2026년 7월 28일

검토 범위
제출 패키지(체크리스트·ERD·흐름도·약관·처리방침·관리자 권한) 및 기술팀 설명 자료

검토 관점
IT·플랫폼·개인정보보호법 중심 1차 실무 검토 (의료분쟁·세무·상표 등은 별도)

본 문서는 AI가 IT·개인정보 실무 관점에서 작성한 사전 검토 시뮬레이션입니다. 변호사·법률 자문 계약을 대체하지 않으며, 실제 소송·과징금·행정 지도에 대한 확답이 아닙니다. 최종 의사결정 전 반드시 대한변협 등록 변호사의 서명·날인 의견서를 받으십시오.
■ 운영(공개 배포) 판단: 조건부 가능

서비스 모델 자체(익명 건강 커뮤니티 + 본인 일지, 의료행위·결제·AI 진료 없음)는 위법으로 보기 어렵습니다.
다만 현재 약관·처리방침·고지·연령 확인·운영정책이 실제 기능과 어긋나거나 미비하여, P0 5건을 반영하기 전 herpfree.co.kr 전면 공개는 권하지 않습니다.
P0 반영 후 제한적·단계적 오픈(베타 공지 포함)은 가능하다고 봅니다. 예상 소요: 문서·고지 중심 1~2주.

A. 서비스 전체

현재 서비스 구조 그대로 배포 가능한가?
☑ 조건부
의견: 기능 구조는 가능. 문서·고지 P0 미반영 시 불가에 가깝게 판단.
의료법, 개인정보보호법 및 서비스 운영 관련 법령상 문제가 없는가?
☑ 조건부
의견: 의료행위 오인만 지속 고지하면 의료법 리스크는 관리 가능. 개정 PIPA(민감정보·동의·파기) 및 플랫폼 고지 의무가 핵심.
「의료행위가 아닌 정보 제공 및 커뮤니티 서비스」 구조로 충분한가?
☑ 가능
의견: 진단·처방·개별 처方·원격진료 유도 없음. 칼럼·유튜브에 「참고용·전문의 상담 권고」 유지.
오픈 전 반드시 수정·삭제해야 하는 기능이 있는가?
☑ 없음
의견: 기능 삭제보다 약관·처리방침·고지·운영정책 정합이 우선. 관리자 게시글 수정은 유지 가능하나 약관 반영 필수.
오픈 전 반드시 추가해야 하는 약관·고지·운영정책이 있는가?
☑ 있음
의견: 커뮤니티 운영정책(신고·금지행위·사진·정지), 사이트 하단 운영자 고지, 처리방침·약관 보완 필수.
사업자등록 전 개인 명의 운영 · 전자상거래법 신고
☑ 조건부
의견: 현재 유료·자체 판매 없음 → 통신판매업 신고 대상 아님. 다만 정보통신망 이용촉진 및 정보보호 등에 관한 법률상 영리 목적 웹서비스 운영자 표시(상호·연락처 등)는 사업자등록 전에도 필요. 사업자등록은 수익·광고·제휴 발생 시 검토.
현재 그대로 herpfree.co.kr 공개 배포 가능한가?
☑ 조건부
의견: P0 완료 전 공개 배포 비권고. 완료 후 공개 가능.

B. 회원가입 · 연령 · 인증

회원가입 방식이 적절한가?
☑ 가능
의견: 이메일·OAuth·필수 동의 구조 적절.
이메일·닉네임만 수집 — 최소수집
☑ 가능
의견: 가입 단계 최소수집 원칙 충족. 일지·게시는 이용 과정 수집으로 별도 동의로 커버됨.
소셜로그인 구조
☑ 조건부
의견: provider ID만 저장은 적절. 처리방침에 OAuth 위탁·제3자(카카오·네이버·구글) 명칭·목적·보관 기간 기재 필요(P0).
14세 미만 가입 처리 (현재 체크만)
☑ 조건부
의견: 민감정보(건강) 처리 서비스에서 체크만은 취약. P0: ① 만 14세 이상만 가입(연령 확인 문구 강화) 또는 ② 14세 미만 시 법정대리인 동의 절차. 실무상 ①이 단순.
성인(만 19세)만 가입이 더 적절한가?
☑ 아니오
의견: 필수는 아님. 14세 이상 + 민감정보 동의로도 가능하나 연령 검증 강화는 필요.
본인인증 필요 여부
☑ 불필요
의견: MVP 단계 필수 아님. 분쟁·재가입 남용 증가 시 P1에서 검토.
필수·선택 동의 구조
☑ 가능
의견: 민감정보·통계·마케팅 분리 적절. 서버 검증 유지.
동의 이력(버전·시각)
☑ 가능
의견: append-only 이력 적절. 약관 개정 시 재동의 프로세스는 P0(약관 조항).

최종 의견

Herfree는 불법 서비스가 아닙니다. 건강 관련 민감정보를 다루므로 일반 SNS보다 고지·동의·약관·운영정책의 정밀도가 요구됩니다. 기술 구현(본인 일지 접근통제, 탈퇴 삭제, 선택 통계)은 양호한 편이나, 법률 문서와 실제 기능(정지·운영자 수정·비공개 열람)의 정합이 미흡합니다. P0 5건은 대부분 문서·고지·푸터 수정으로 해결 가능하며, 코드 대규모 변경 없이 1~2주 내 「조건부 가능」→「가능」 전환이 현실적입니다.
