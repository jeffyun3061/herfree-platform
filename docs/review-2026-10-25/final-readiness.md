# 운영 적용 전 점검 기록 (2026-10-27 갱신)

## 판정

**현재 운영 배포 불가(NO-GO).** 이 브랜치는 검토 후보이며 운영 `main` 병합과 배포를 하지 않았다. 코드 검증 통과와 실제 서비스의 보안·복구 검증은 별개다. 기존 계획의 사용자 검토와 별도 운영 적용 승인도 아직 남아 있다.

## 이번 재점검에서 고친 것

* 글쓰기의 `비밀글로 작성`은 글 공개 범위를 바꾸지 않고 닉네임만 숨기는 기능이었다. `익명으로 작성`으로 고치고 공개 범위는 별도 설정을 따른다고 화면에 명시했다. 홈·메뉴의 `비공개 커뮤니티` 일괄 표현도 실제 공개 글이 있는 서비스에 맞게 고쳤다.
* 개인정보처리방침 초안의 `관리자 접근망/CIDR 제한` 보장을 삭제하고 후보 코드의 역할·MFA 통제에 맞췄다. 회원 전용 글 제목 공개 선택과 익명 고민 본문 공개 범위를 명시했다. 방침·웹 시행일과 신규 가입 동의 버전을 함께 갱신했다. **기존 회원 공지·필요한 재동의와 실제 배포일 기준 시행일은 운영·법률 검토 후 확정해야 한다.**
* 법적 문구 정합성 검사에 제목 공개와 익명 고민 공개 범위를 추가했다.

## 확인한 증적

* 프론트 ESLint 통과. 합성 OAuth 설정을 사용한 Next.js **Webpack** 운영 빌드 통과. 기본 Turbopack 빌드는 Windows 샌드박스의 하위 프로세스 생성 오류였고, 일반 샌드박스의 Webpack 정적 페이지 생성도 파일 권한 오류였다. 이 환경 제약을 우회한 빌드 결과와 GitHub Linux CI는 구분해서 기록한다.
* 합성 계정·글로 PC Chromium, 모바일 Chromium, iPhone WebKit에서 제목 공유 선택·제목 수정 재선택·비회원 로그인 화면·익명 선택과 실제 공개 범위 **12/12 통과**. 설치형 앱 WebView와 실제 메신저는 아직 미검증이다.
* `verify-legal-policy-alignment.ps1`의 코드·문안 정합성 검사 통과, 운영 사실 미평가 경고 1개. 엄격한 운영 검사는 운영자·담당 창구 확인, 메일 사업자·국가·AWS 리전·국외 접근 검토, 방침 버전과 검토 기록의 **8개 운영 선언** 및 실제 공개 방침의 정합성을 요구한다. 개인 집 주소·담당자 개인 성명은 일괄 필수 입력으로 요구하지 않는다. 선언 입력만으로 법률상 적합성이 증명되는 것은 아니다.
* 스테이징 애플리케이션 커밋 `bddb71d783f56e29b26a67c55938be38c4bfd2e3`의 [배포·이미지 보안 스캔·스모크 17개·변경 기능 8개 검증](https://github.com/jeffyun3061/herfree-platform/actions/runs/40459528209)이 통과했다. 별도의 복원 후 스테이징 앱 재시작 보완은 [PR #185](https://github.com/jeffyun3061/herfree-platform/pull/185)에서 검증하고 `develop`에 반영했다. 이후 동의 기능 변경은 다시 검증해야 한다.
* 6시간 백업 실물·암호화·보관기간을 AWS에서 확인했고, 실제 스테이징 검증 이미지로 격리 복원과 핵심 기능·암호화 데이터 복호화 검사가 성공했다. 훈련 검증은 278초, 시작 시 백업 나이는 99초였으며, 실제 서비스 장애의 전체 복구 시간을 보장하는 수치는 아니다. 스테이징 중지·원래 권한 복구·임시 복원 디스크 삭제와 복원 역할 분리를 확인했다.
* 추가 검토에서 문의·상담 작성/수정 응답의 본인 열람 오류와 비로그인 익명 고민 검색의 공개범위 누락을 수정했다. 해당 백엔드 테스트 35개와 공유·편집·MFA 프론트 테스트 14개가 통과했다. 실제 MySQL 검색 검증은 최신 CI에서 확인한다.
* 운영·배포 스크립트 테스트는 38개 통과, Linux 전용 1개는 로컬에서 제외됐다. 후보 `npm audit`는 알려진 취약점 0건이다. 기본 운영 절차에서 과거 RDS 신규 생성 호출을 제거했고, 운영 GitHub 배포 경로는 AWS 변경 전에 방침 검토를 검사한다. Amplify `main` 자동 빌드가 켜진 동안에는 병합 자체가 운영 프론트 적용으로 이어질 수 있어, 별도 승인 전 `main` 병합을 금지한다.
* 익명 고민의 공개 확인은 건강정보 처리에 대한 별도 동의·철회와 다르다. 현재 개인일지 동의는 커뮤니티에 적용되지 않고, 글·댓글 삭제는 DB 원문을 즉시 파기하지 않는다. 사용자는 새 익명 고민의 동의 철회 시 즉시 숨기고 삭제 요청을 접수하는 방식을 선택했으며, 해당 기능은 아직 구현·법률 검토 전이다. 엄격한 운영 배포 검사는 이 상태에서 실패하도록 보완했다.

## 운영 전 차단 항목과 담당

1. **운영자·개인정보 담당자:** 실제 운영 주체와 연락·권리 요청 처리 절차, 개인정보 보호책임자, 메일·분석 수탁자, 보유기간·국외 접근 사실을 증빙으로 확인한다. 개인정보처리방침 변경의 공지/재동의 필요성과 익명 건강 고민 공개 동의 방식, 운영자 답변의 의료광고·의료행위 표현을 한국 법률 전문가와 검토한다. 운영 담당자에게 의료 조언 금지/신고·삭제·침해 대응 교육을 진행한다.
2. **AWS 관리자:** 스테이징 조회 권한과 MFA 암호화 키는 확인했다. AWS root MFA는 켜져 있고 관리자 권한 IAM 사용자는 MFA가 없어 사용자가 나중에 등록하기로 했다. 실제 사이트 운영자 계정의 MFA도 본인 확인 후 등록하고, 경보 이메일 도달을 증명한다. 민감정보 키는 단순 교체하지 않는다.
3. **개발/운영:** 스테이징 기능 검증과 격리 복원은 통과했다. 별도 커뮤니티 건강정보 동의·철회 및 삭제 요청을 구현·법률 검토하고, 변경 후 재검증한다. 실물 iPhone/Android 앱 WebView와 카카오톡 미리보기도 확인한다.
4. **배포 전:** 최종 SHA의 CI 통과, 운영 백업 성공, 현재 실행 이미지 digest와 직전 정상 이미지 3개, 정책 시행일·공지, 롤백 절차를 한 문서에서 확인하고 사용자에게 제시한다. 별도 운영 적용 승인을 받은 뒤에만 병합·배포한다.

새 익명 고민 동의 기능의 추가 차단 사항: 첨부 업로드와 동의의 연결·철회 후 캐시 및 업로드 처리, 복원 전 철회 표식 재적용은 아직 완성되지 않았다. 현재 복원 성공은 기존 데이터의 복원과 복호화를 확인한 결과이며, **철회 이전 백업을 복원해도 철회한 내용이 다시 공개되지 않는다는 검증은 아니다.** 독립 원장과 누락·부분 실패 시 공개 기동 차단을 포함한 해결책을 구현하고 재현 시험하기 전에는 이 기능을 운영에 출시하지 않는다.
