# Herfree 운영자 매뉴얼

이 문서는 개발자가 아닌 서비스 운영자가 Herfree를 안전하게 관리하기 위한 최소 절차입니다.
건강정보 노출, 관리자 계정 탈취, DB·백업 유출이 의심되면 직접 판단해 넘기지 말고 [`health-data-security-standard.md`](./health-data-security-standard.md)의 SEV-1 절차로 즉시 보고합니다.

## 운영자가 매일 확인할 것

| 항목 | 확인 위치 | 조치 |
|------|-----------|------|
| 신규 신고 | 관리자 > 신고 관리 | 명백한 광고·개인정보 노출·공격성 글은 숨김 처리 |
| 문의/비공개 상담 답변 | 관리자/운영자 계정 | 본인 글 또는 운영자 범위에서만 확인 |
| 로그인/비밀번호 재설정 장애 | 서버 로그/CloudWatch | SMTP 실패가 반복되면 개발자에게 전달 |
| 이미지 업로드 장애 | 서버 로그/CloudWatch | S3 권한·버킷·용량 이슈 확인 요청 |

## 운영자가 해도 되는 작업

- 신고된 게시글/댓글 숨김 또는 복구
- 사용자 계정 정지/해제
- 부적절 닉네임 초기화
- 공지 등록/수정
- 칼럼/영상 노출 여부와 정렬 순서 조정
- 개인정보 삭제 요청을 개발자에게 전달

## 관리자 화면 탭별 사용 기준

| 탭 | 주요 업무 | 주의할 점 |
|------|-----------|-----------|
| 대시보드 | 회원, 게시글, 신고, 퍼널 이벤트 흐름 확인 | 이벤트에는 개인정보 원문이 없어야 한다 |
| 신고 | 신고 접수 승인/반려, 게시글·댓글 숨김 | 삭제보다 숨김을 우선하고, 사용자 신고는 회원 탭에서 제재 사유를 남긴다 |
| 숨김 관리 | 숨김 처리된 게시글·댓글 복구 | 복구 전 신고 사유와 개인정보 노출 여부를 다시 확인한다 |
| 일지 통계 | 개인일지 사용 흐름 확인 | 개인별 건강 기록 원문을 운영자가 조회하지 않는다 |
| 공지 관리 | 서비스 공지 작성, 숨김, 고정, 순서 조정 | 잘못된 공지는 삭제보다 숨김 후 수정한다 |
| 칼럼 관리 | 칼럼 작성, 대표 이미지, 카테고리, 정렬 관리 | 의학적 확정 표현이나 개인정보 사례가 들어가지 않게 확인한다 |
| 영상 관리 | 유튜브 영상 등록, 추천/노출/정렬 관리 | 외부 영상 URL과 썸네일이 정상 노출되는지 확인한다 |
| 회원 | 회원 검색, 정지/해제, 닉네임 초기화 | 정지는 제재 사유와 운영 메모를 남기고 처리한다 |

회원 정지는 단순 상태 변경보다 `제재 설정`을 우선 사용한다.
제재 사유와 메모가 남아야 이후 이의제기나 운영 인수인계 때 판단 근거가 된다.

## 운영자가 직접 하면 안 되는 작업

- AWS root 계정으로 일상 운영
- DB 직접 수정
- `.env.prod` 임의 수정
- S3 버킷 퍼블릭 쓰기/읽기 정책 변경
- 관리자 권한을 본인 판단으로 추가 발급

## 사용자 문의 대응

### 비밀번호 재설정 메일이 오지 않음

1. 스팸함 확인을 안내한다.
2. 같은 이메일로 5분 뒤 다시 요청하게 한다.
3. 여러 사용자에게 동시에 발생하면 SMTP 장애로 보고 개발자에게 전달한다.

운영 로그에는 재설정 URL이나 토큰이 남지 않아야 한다. 운영자가 토큰을 요구하거나 전달하면 안 된다.

### 가입 이메일을 기억하지 못함

1. Herfree의 아이디는 가입 이메일임을 안내한다.
2. 자동 이메일 찾기는 계정 존재 여부가 노출될 수 있어 제공하지 않는다.
3. 사용자가 예상 이메일, 소셜 로그인 사용 여부, 가입 시기 정도를 정리해 문의하면 운영 정책에 따라 본인 확인 후 처리한다.
4. 운영자가 임의로 DB를 직접 조회하거나 이메일 목록을 전달하지 않는다.

### 계정 정지 문의

1. 관리자 화면에서 계정 상태와 사유를 확인한다.
2. 정지 해제는 운영 정책에 맞을 때만 처리한다.
3. 정지/해제 작업은 감사 로그에 남는다.

### 닉네임 변경 문의

1. 일반 회원은 닉네임을 30일에 한 번만 변경할 수 있다.
2. 닉네임을 변경하면 기존 글과 댓글의 표시 닉네임도 함께 바뀐다.
3. 부적절한 닉네임은 관리자 화면에서 초기화할 수 있다.
4. 사용자 직접 변경과 관리자 초기화는 `nickname_change_history`에 이력으로 남는다.

### 개인정보 삭제 요청

1. 요청자의 계정 식별 정보를 확인한다.
2. 개발자에게 삭제/익명화 처리 요청을 전달한다.
3. 처리 완료 후 사용자에게 결과를 안내한다.

## 개발자에게 전달해야 하는 상황

- 관리자 화면에서 401/403이 반복된다.
- 신고 숨김/복구, 회원 제재, 공지·칼럼·영상 저장이 실패한다.
- 비밀번호 재설정 메일 실패가 여러 사용자에게 동시에 발생한다.
- 이미지 업로드 또는 이미지 조회 실패가 반복된다.
- 운영자가 보지 않아야 할 개인정보 원문이 로그나 관리자 화면에 보인다.
- DB 직접 수정이 필요해 보이는 요청이 들어온다.
- 목록 화면이 느려지거나 페이지 이동에 3초 이상 걸리는 현상이 반복된다.
- 댓글이 많은 글에서 댓글 페이지 이동이나 숨김 처리가 지연된다.

## 데이터 증가 시 점검 기준

- 게시글, 댓글, 회원, 신고, 공지, 칼럼, 영상 목록은 페이지 단위로 조회한다.
- API page size는 서버에서 최대 50개로 제한한다. 운영자가 한 화면에 모든 데이터를 보려고 DB를 직접 조회하지 않는다.
- 긴 제목, 긴 이메일, 긴 댓글, 긴 URL은 화면을 밀어내지 않고 줄바꿈되거나 2줄 이내로 줄인다.
- 회원이 늘어나면 회원 관리에서는 전체 목록 탐색보다 이메일, 닉네임, 회원 ID 검색을 우선한다.
- 신고와 숨김 처리가 밀리면 운영자가 처리할 수 있는 기준과 우선순위를 먼저 정하고, 자동화는 개발자에게 별도 요청한다.

## 로컬 대량 데이터 QA

운영 DB에는 테스트 데이터를 넣지 않는다. 로컬 또는 스테이징에서만 확인한다.

로컬에서 `local` 프로필과 `app.demo-seed.enabled=true`를 켜면 페이지 QA용 데이터가 자동 보강된다.

- 커뮤니티 FREE 게시판 글: 120개까지 보강
- 테스트 게시글 댓글: 120개까지 보강
- 칼럼: 80개까지 보강

확인할 화면:

- `/community`: 2페이지 이상 이동, 최신순/댓글순/인기순 전환, 긴 제목 표시
- `/community/posts/{id}`: 댓글 2페이지 이상 이동, 긴 댓글/긴 URL 줄바꿈
- `/contents`: 칼럼 2페이지 이상 이동, 긴 본문 상세 표시
- `/admin?tab=moderation`: 숨김 관리 목록 페이지 이동
- `/admin?tab=contents`: 칼럼 관리 목록 페이지 이동과 정렬·고정 설정 접힘 상태

대량 QA 후 운영 배포 전에는 운영 DB에 `demo*@herfree.local`, `페이지 테스트` 데이터가 없는지 다시 확인한다.

## 관리자 계정 보안 수칙

- 운영자 계정은 개인별로 분리한다.
- 비밀번호는 다른 서비스와 재사용하지 않는다.
- 공용 PC에서 관리자 로그인을 하지 않는다.
- 퇴사/계약 종료 즉시 관리자 권한을 회수한다.
- MFA 도입 전까지 SUPER_ADMIN 계정은 최소 인원만 보유한다.
