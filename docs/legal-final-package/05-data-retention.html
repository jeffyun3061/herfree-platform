개인정보 보관 · 삭제 (현행 구현 기준)

Herfree · 2026년 7월

별도 「개인정보 보관·파기 정책」 문서는 아직 없습니다. 아래는 현재 시스템·처리방침·내부 기준이며, 변호사 검토 후 확정·문서화 예정입니다.

1. 회원 탈퇴 시 (즉시 처리)

데이터처리
개인 일지 전체물리 삭제
이메일·비밀번호비식별 값으로 교체, 계정 DELETED
OAuth 연결삭제
게시글·댓글익명 처리 (내용 유지, 작성자 표시 제거)
게시글 사진S3에서 삭제
스크랩·북마크삭제
닉네임·프로필withdrawn_{id} 등으로 마스킹

2. 회원 이용 중

항목보관
계정·프로필탈퇴 또는 삭제 요청 전까지
동의 이력가입·변경 시점 기록 (append-only)
게시글·댓글작성자 삭제 시 soft delete 또는 익명

3. 로그 · 백업 (내부 권장 — 미확정)

구분현재·권장
애플리케이션 로그30~90일 (내부 logging-policy.md)
관리자 감사 로그최소 1년 권장
분석 이벤트 (IP 해시)운영 통계 목적 필요 기간 (구체 일수 미확정)
RDS 백업AWS 자동 백업 (단기, 운영 설정)

4. 로그에 남기지 않는 것

  • 비밀번호, JWT, 재설정 토큰 원문
  • 일지·게시글 본문 전문
  • OAuth 토큰

5. 처리방침과의 차이 (검토 필요)

  • 방침: 「필요한 기간」「법령에 따라」— 구체 보관 일수 미기재
  • 장기 미접속 회원 자동 파기 — 미구현
  • 백업·로그 내 탈퇴자 데이터 — 보관 기간 법률 자문 필요
