# 커뮤니티 건강정보 동의·철회 설계 검토안

2026-10-27. **운영 적용 승인이나 적법성 인증이 아닌 설계 검토안이다.** 사용자는 새 익명 고민의 민감정보 동의 철회 시 **즉시 숨기고 삭제 요청을 접수**하는 방식을 선택했다. 동의 원장·요청 큐·처리기한·예외 보존·통지 절차는 구현과 법률 검토가 필요하다. 이 문서 자체는 동의 상태·공개범위·원문·기존 데이터를 변경하지 않는다.

## 확인한 현재 동작

- 익명 고민의 `publicDisclosureAccepted`는 공개 확인 요청값이다. 별도 민감정보 처리 동의의 목적·항목·보유기간·문안 버전·시점을 저장하지 않는다. 글 수정·댓글에는 같은 공개 확인도 없다.
- 가입의 `agreeSensitive` 및 `HealthDataConsentService`는 개인일지 목적이다. 철회는 개인일지만 삭제한다. 커뮤니티 처리 동의로 자동 승계하거나 범위를 확장하지 않는다.
- `Post.user`와 `Comment.user`는 내부 회원 ID에 연결된다. 익명 표시는 외부 닉네임 비노출이며 완전한 익명화가 아니다.
- `UserService.withdraw()`는 기존 계정 식별값을 마스킹·대체하고 소셜 인증연결·개인일지·게시물 이미지를 정리한다. 내부 회원 행·작성자 연결·게시물과 댓글 본문은 유지한다.
- 글·댓글 삭제는 공개 상태를 변경하는 soft delete다. 현재 동작을 원문 파기 또는 민감정보 동의 철회 완료로 설명하지 않는다.

## 결정이 필요한 구현 범위

| 항목 | 제안 | 미확정 사항 |
|---|---|---|
| 새 익명 고민 글·댓글 | 커뮤니티 건강정보 목적의 별도 동의와 공개 확인을 구분하고 서버에서 검증 | 실제 처리 항목·목적·보유기간, 공개 제공의 법적 근거, 운영자 답변 범위 |
| 일반 게시판·문의 | 건강정보가 예상되는 작성·댓글 경로도 함께 검토 | 모든 작성에 목적별 동의를 적용할지, 건강정보 없는 이용을 별도로 제공할지 |
| 선택 거부 | 가입·읽기는 유지하고 본인 전용 개인일지 경로 제공 | 동의 거부 시 제한하는 기능과 안내 문구 |
| 동의 증빙 | 사용자·대상 ID·목적·정책 버전·동의/철회 시각·공개범위의 최소 원장 | 증빙 보유기간과 접근권한. 건강 본문·IP·기기 지문은 복제하지 않음 |
| 철회 즉시 조치 | 해당 범위의 공개 API·검색·공유 미리보기·첨부 접근 중단 | 글별/댓글별 철회와 목적 전체 철회 중 어느 범위를 제공할지 |
| 원문·첨부 처리 | 즉시 공개 중단과 원문 파기를 구분해 처리 결과 안내 | 실제 파기, 신고·분쟁상 제한 보관 사유·기간·통지 절차 |
| 백업·복원 | 파기 대상이 복원으로 다시 공개되지 않도록 최소 삭제 표식 적용 | 백업 보관기간·만료 파기·복원 재적용과 증빙 기간 |
| 기존 글·회원 | 기존 동의 자동 생성·임의 삭제·공개범위 변경 금지 | 과거 수집 근거와 재동의·제한·파기 필요성을 별도 검토 |
| 개인일지·통계 | 기존 목적·동의·철회를 독립 유지 | 커뮤니티 철회와 교차 삭제가 생기지 않도록 범위 명시 |

공개 글을 작성하지 않는 대안은 `/journal`의 본인 전용 기록이다. 회원 공개는 모든 로그인 회원에게 표시되므로 비공개 대안으로 부르지 않는다. 개인일지 이동 때 초안을 URL·브라우저 저장소로 자동 전달하지 않는다. 외부 검색·공유 서비스에 이미 저장된 사본은 서비스 내 삭제만으로 즉시 모두 회수된다고 약속하지 않는다.

## 구현 검증 기준

1. 동의하지 않은 계정의 해당 범위 신규 글·수정·댓글을 서버에서 차단하고, UI 우회 요청도 동일하게 처리한다.
2. 동의 원장은 문안 버전을 확인하고 최소 증빙만 저장한다. 기존 회원을 자동 동의 처리하지 않는다.
3. 철회 범위에 포함된 글·댓글·이미지·공유 미리보기를 권한별로 검사한다. 원문 파기 여부와 단순 공개 중단을 구분해 검증한다.
4. 개인일지·통계·다른 게시판에 동의나 삭제가 번지지 않으며, 재동의만으로 과거 파기 자료가 복구되지 않는다.
5. DB 백업 복원 뒤 철회·삭제 표식을 재적용해 다시 공개되지 않는지 격리 환경에서 검증한다.

## 법률 검토 근거

건강정보에 해당하는 개인정보를 동의에 근거해 처리한다면 일반 개인정보와 구분한 동의가 필요하다. 공개 위험을 예상하는 서비스는 공개 가능성과 비공개 선택 방법도 먼저 알려야 한다. [개인정보 보호법 제23조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029927029)

동의에는 목적·항목·보유기간·거부권과 거부 시 영향이 포함돼야 한다. 구체적 보유기간과 공개 제공 근거는 실제 운영 사실에 따라 검토한다. [제15조 제2항](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398563)

동의 철회·처리정지에는 파기 등 필요한 조치와 예외 사유·통지 규정이 있다. 임의 영구 보관이나 무조건 일괄 삭제를 확정하지 않고 실제 사유와 범위를 검토한다. [제37조](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1020398509)
